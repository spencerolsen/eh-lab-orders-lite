# LAB-06: Catalog: see and add lab tests

- **Status:** In progress
- **Type:** Vertical slice
- **Depends on:** LAB-05 (Checks on every pull request)
- **Unblocks:** LAB-07 (Catalog: edit and activate or deactivate tests), LAB-11 (Orders: see orders on the home page)
- **Branch:** `lab-06-catalog-list-and-add`

## Description

After this task, a user can open the Lab tests page under Catalog in the navigation, see every lab test the clinic offers (code, name, price, turnaround in business days, active or not), and add a new test with a form.

This is the first vertical slice, so it also proves the pattern the later slices copy: migration, repository, route, shared Zod schema, React page, tests, docs. It comes before orders because an order is made of catalog tests. Editing and deactivating are left to LAB-07 to keep this review small.

## Requirements

**Data**
- New plain SQL migration creating `lab_tests`: `id uuid` primary key (generated by the database), `code text not null unique`, `name text not null`, `price_cents integer not null`, `turnaround_days integer not null`, `is_active boolean not null default true`, `created_at` and `updated_at` (`timestamptz`, default now).
- Database checks as well as code checks: `price_cents >= 0`, `turnaround_days >= 1`, `code = upper(code)`, `code` and `name` not blank.
- Seed exactly 8 tests with realistic lab codes: CBC, CMP, LIPID, A1C, TSH, UA, VITD, CULT. Names are the usual ones (for example "Complete Blood Count"), prices are whole cents, turnarounds are between 1 and 5 business days, and all 8 are active. The seed goes in the `pnpm db:seed` command built in LAB-02, gives every seeded row a fixed UUID and inserts with `on conflict (id) do nothing`, so it can run twice and leaves the same rows (`pnpm dev` always runs the seed, LAB-02). It is never run by unit or integration tests (the e2e setup in LAB-21 loads the seed into lab_orders_e2e).

**API**
- `GET /api/lab-tests` returns 200 with an array of `{ id, code, name, priceCents, turnaroundDays, isActive }`, sorted by code, including inactive tests.
- `POST /api/lab-tests` body `{ code, name, priceCents, turnaroundDays }` returns 201 with the created test. New tests are always active.
- The schema trims and upper-cases `code` (2 to 20 characters, letters, digits and hyphens). Name is trimmed, 1 to 100 characters. `priceCents` is an integer >= 0. `turnaroundDays` is an integer >= 1. The schema is strict: unknown extra fields return 400 `VALIDATION_ERROR`.
- 400 `VALIDATION_ERROR` with `details` per field for bad input. 409 `DUPLICATE_TEST_CODE` when the code exists: the database unique violation is translated, with no check-then-insert, so two simultaneous requests cannot both win.
- Schemas live in `src/shared/` and are used by server and web. Code goes in `src/server/catalog/{routes.ts,repo.ts}`; the route parses explicitly with Zod and calls the repo directly (no rule here needs a service). Rows pass through the typed mapper.

**UI**
- `src/web/catalog/`: Lab tests page at `/catalog`, linked from the navigation. Columns: Code, Name, Price (`$12.50`), Turnaround ("3 business days", "1 business day"), Active (Yes or No). Empty state, loading state, and an error state that shows the request id.
- Add form on the same page: code, name, price in dollars, turnaround in business days. Field errors appear under each field, including "This code already exists" from the 409. On success the form clears and the new test appears without a reload (TanStack Query invalidation).
- A pure helper `parseDollarsToCents` in `src/shared/money.ts` uses string handling, never floating point. It accepts `12`, `12.5`, `12.50` and rejects negatives, more than two decimals, commas and text. `formatCents` does the reverse for display.

**Logging**
- `info` `lab_test.created` with `labTestId`. `warn` `lab_test.duplicate_code` with no code value. Request lines come from LAB-03.

## Acceptance criteria

- [ ] After `pnpm db:seed`, the Lab tests page lists exactly 8 tests in code order: A1C, CBC, CMP, CULT, LIPID, TSH, UA, VITD.
- [ ] Adding code `demo-09`, name "Demo Panel", price `19.99`, turnaround `2` shows `DEMO-09`, `$19.99`, "2 business days" without a reload, and the database holds `price_cents = 1999`.
- [ ] Adding code `cbc` (any letter case) shows "This code already exists" under the code field and creates no second row; the API returns 409 `DUPLICATE_TEST_CODE`.
- [ ] A blank name, a price of `-1`, `12.345` or `abc`, and a turnaround of `0` or `1.5` each show a message under the right field and send no request.

- [ ] `POST` with a string `priceCents`, a missing `code`, or an unknown extra field returns 400 `VALIDATION_ERROR` with the error shape and a request id.
- [ ] The database rejects a row with a negative price or a zero turnaround (direct SQL in the integration test).
- [ ] Running `pnpm db:seed` twice leaves exactly 8 rows.
- [ ] A server error shows a plain message with the request id, not a blank table.
- [ ] The docs/process.md slice log entry and test log entry were written in the same pull request.
- [ ] This slice's manual checks are added to docs/acceptance-checklist.md under the checkpoint that covers it (Checkpoint 1).

## Tests

- **Unit:** `parseDollarsToCents` (`"12.50"` to 1250, `"0.1"` to 10, `"19.99"` to 1999; rejects `"12.345"`, `"-1"`, `""`, `"1,000"`); `formatCents`; the Zod schema (trim and upper-case, boundaries on price and turnaround, unknown field rejected).
- **Integration (real Postgres, real HTTP):** list returns the rows sorted by code; create returns 201; duplicate code returns 409 `DUPLICATE_TEST_CODE`; invalid body returns 400 with field details; check constraints reject bad rows; seed twice gives 8 rows; the mapper fails loudly when a column is missing.
- **E2E:** none here; the browser journeys are LAB-21.
